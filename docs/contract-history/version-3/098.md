Review of the catalog-close fix, #47 (2026-09-26): C-30.1 now says when a catalog run may write, its exit statuses when it declines (3; 4 for a fence that is not a pipe) and that the service logs a declined run it still tracks; a declined run had exited 0, so a false decline left the catalog stale without a word. The fence sits above descriptor 2: in a daemon with stdin closed it had been fd 0, which the run's /dev/null stdin replaced. C-25.3: `close()` finishes the file ops already running and runs none after, and a file op never makes the state root; an `attachment.add` (or a worktree create) that finished after `close()` had made the removed root again.
