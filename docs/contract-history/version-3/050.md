C-8.4, C-13.4 (2026-10-01, the four notes #81 left on #76; design `docs/desktop/retention-archive.md` revision 5): a file is matched on its ctime too, and one that had other links when archived whose ctime alone moved is deleted only if its bytes still hash to the archived sha256 (a same-size write whose mtime was put back was deleted). A job whose tree another tool holds aside (`<anything>.<name>` beside it, as `disk-guard` names it) is kept, and so is one whose tree left or came back while it was being retired. The tree admission allocated before `jobs.worktree` recorded it (`worktrees/<job id>`) is the job's own allocated worktree. A job whose tree and workdir are both gone finds its registration and repository through the repositories the store's jobs are in; a salvage ref whose repository cannot be found says so.
