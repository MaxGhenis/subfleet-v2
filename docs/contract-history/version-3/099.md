Reviews of the catalog-close follow-ups, 39223c9 (2026-09-26): C-25.3 says the conversation service opens a native session's files only as regular files and never blocks in `open()`. `close()` had begun to wait for the file ops already running, and one handed a FIFO where a Codex rollout belonged (`conversation.history`, a handoff) blocked in `open()` until a writer came, holding `close()` with it. C-30.1 now says a run checks before each file it publishes rather than that it writes only while its service is open: it publishes by path, so a root removed or replaced after a check can fail the write (exit 1) or receive it; and the service names a reason only for exits 3 and 4.
