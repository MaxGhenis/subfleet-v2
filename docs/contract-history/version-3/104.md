C-28.1 (2026-09-27, review of 1808f61): the driver's check judges a stored copy as an add does. It read the copy with `read_bytes()`, which followed a symlink and blocked on a FIFO at the copy's name for good, holding the conversation tick that builds turns and every tick after it (C-25.3's regular-file, never-blocking rule, now for attachments). The daemon's own copy is also of the row's size, read at most one byte past it, owned by its user, with no second link and no group or other mode bits: a re-add had kept a copy made readable by others or hard-linked from outside, and hashed a stray file of any size in full. A re-add also records the copy's path, so a moved state root no longer leaves a row naming the old one.
