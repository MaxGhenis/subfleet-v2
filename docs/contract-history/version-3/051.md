C-8.4, C-13.4, C-5.1 (2026-09-30, final review of e50716e8; design `docs/desktop/retention-archive.md` revision 4): inside a regenerable directory's tool entries only what a rule proves regenerable is deleted without a copy (a file an installed distribution's RECORD lists with a matching sha256, from a distribution uv installed from an index or a network URL; bytecode with a magic number beside its source; a tool cache's own file names), and everything else there, all of `node_modules` included, is archived; git's names and the disk's are compared NFC-normalized and casefolded. Every report of freed bytes also reports `added_bytes`, what the archive adds (bundle, manifest, summary, rows, byte copies), and the log lines the net. A job whose baseline no network remote holds (a host on this machine is no network remote) and whose bundle would carry more than `retention.remote_less_history_bytes` (default 64 MiB) of history is kept. A job registered in a repository inside another job's tree pins that job while it has rows, and is kept while that tree is not there. An admin directory reduced to `index` and `logs/` is no registration; its bytes are archived. A published archive keeps no progress log. Retention's children run under the `utility` QoS clamp and its in-process steps with lowered thread I/O.
