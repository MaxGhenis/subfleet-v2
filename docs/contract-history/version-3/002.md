C-9.6 (2026-10-13, defect D-HOLD1): an operator hold keeps its own closure row. `Store.put_closure` kept one open closure per lane and scope, so a weekly limit reported on a held lane (by an attempt that was already running) rewrote the hold's row as its own; the usage read that later saw the window reset released it, and the lane was admitted hours before the hold's end. The reverse merge dropped a limit that ended before a longer hold, so `lanes release` opened a lane that was still limited. Holds (`operator-hold`, `auth-dead`) and limits now each keep their own row; the v1 importer's cooldown merge follows the same rule. A hold absorbed before this change stays absorbed: `lanes hold` it again to give it its row.
