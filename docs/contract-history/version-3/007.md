C-25.6 (2026-10-11, defect D-PB1; Max agreed in d1350 that it is fixed first): a controlling terminal no longer admits a caller to the person-only operations. Only the installed app's executable does, or on a development state root the development build named when the daemon started (D-21), after the guardian and marker vetoes, which are unchanged. Before, an agent-started process that had dropped its markers and kept a pseudo-terminal passed as the person once launchd adopted it, and so did a terminal child it forked and any SSH login. Refusing only a caller whose parent is launchd would not have closed it. No `subfleet` subcommand sends a person-only operation, so the CLI is unchanged; the end-to-end tests, which sent them through `script(1)`'s terminal, now send them as a development-app stand-in (`tests/e2e/dev_app.py`) and check that the terminal is refused. The clause also names `conversation.create` and `conversation.handoff` above Ask or on main, which the code already checked (IR-21). Report: `docs/reports/2026-10-11-person-boundary.md`.
