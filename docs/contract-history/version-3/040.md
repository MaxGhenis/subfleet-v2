Review of 31048e67 (F3, 2026-10-05): C-8.4, a `worktree:` lease on a folder inside a job's own allocated worktree, held by anything but that job's retirement, keeps the job as `worktree-lease`, in the pin census (recorded spellings), the selecting transaction and the commit recheck (the canonical spelling), as a turn row there does. Before, `worktree-lease` matched the worktree itself only, and the selecting transaction checked only `worktree:<worktree>`, so once a detached in-place writer in a repository nested in the tree had its attempt quarantined (its job `lost`, its lease kept), nothing kept the job, and retention archived it and deleted its tree under the writer's folder. The leases are read by one key range (`worktree:<folder>/` up to `worktree:<folder>0`), never `LIKE`, which ignores ASCII case and reads `_` and `%` as wildcards. Detached writer reservation still fences only the writer's own folder (known limit, above); turn reservation checks its folder and every folder above it.
