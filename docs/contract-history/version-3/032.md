Admission of a turn nested in a tree being retired (2026-10-05, the known limit the review of the I5 port left; probe in #134's evidence): C-8.4, C-24.5, a turn, writable or read-only, in a repository nested in a job's worktree was reserved while retention held that tree's fence, because reservation read the fence only on the turn's own folder, the nested repository's top level. The commit then rolled the retirement back, but the quarantine had already moved the tree from under the live turn. Reservation now reads the fence on every folder above the turn's too, in the same transaction and by string operations (`folders.above`, `folders.retiring`). The turn waits `lease-held` through the retirement, and its queued job keeps the tree at the commit (`worktree-in-use`). C-6.11, C-24.4: a turn's lease hold names its folder, so its message says retention is removing the tree that folder is in. C-6.5 is unchanged: a detached writer's lease on a folder above holds no turn.
