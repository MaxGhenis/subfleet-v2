## Worktrees leaked by jobs that ended before any attempt (found 2026-09-22; fixed by the C-13.4 amendment)

- Mechanism: admission cuts `worktrees/<job id>/` for a writable job that is not in place when it prepares the workspace (C-6.8), before the route is evaluated. `jobs.worktree` is written only when an attempt is reserved, and retention owned a worktree only through that column. A writable job that was killed, refused, or failed while queued or waiting therefore kept its worktree and its registration in the caller's repository (`git worktree list`). Once retention pruned the job's row, nothing named it.
- On this machine: `~/.subfleet/worktrees/20260919-120636-thesis-tsa-signers` (690 MB, still locked `initializing` by an interrupted `git worktree add`, partial checkout) and `~/.subfleet/worktrees/20260919-120731-thesis-tsa-signers` (1.9 GB, clean). Both are registered in `~/ThesisInstitute/thesis`. Both jobs failed on 2026-09-19 with no attempt, and retention pruned their rows on 2026-09-21. Checked read-only on 2026-09-22: every file in the first is byte-identical to a blob of its HEAD, and it has no file outside HEAD. Both HEADs (6b6a382, 6c42591) are reachable from branches. Removing them loses nothing. The fix never touches a worktree whose job row is gone, so they need removing by hand by whoever owns that checkout: `git -C ~/ThesisInstitute/thesis worktree remove --force --force ~/.subfleet/worktrees/20260919-120636-thesis-tsa-signers`, then `git -C ~/ThesisInstitute/thesis worktree remove ~/.subfleet/worktrees/20260919-120731-thesis-tsa-signers`.
- Fix: branch `fix/prereservation-worktree-leak` (C-13.4, with C-6.8, C-7.4, C-8.4). Such a job owns `worktrees/<job id>/` by its path. It is removed only if what is on disk holds nothing its cut commit does not. The check covers every file and link, the index, and HEAD, and there must be no other job working there. It holds even when the `.git` link is gone, in which case the caller's repository answers. The admission worker removes it on the next pass after the job ends. Retention retries a git failure hourly, but not a refusal, and only for jobs that ended before the admission pass in flight began. Only this path's registration is ever dropped, never with a repository-wide `git worktree prune`. A worktree any attempt used keeps the salvage-first rule.
- For the integrator, when this branch and `fix/admission-route-isolation` (MaxGhenis/subfleet-v2#25) have both merged, whichever merges second should: delete `_discard_fresh_worktree` and its call in `_unroutable`, since it is a second remover that runs rmtree with no checks; make that PR's refusal test run `_admit()` once more before asserting the worktree is gone; replace C-6.12's clause "is removed, since `jobs.worktree` is set only at reservation and retention would never collect it" with "is collected under C-13.4"; and resolve the two doc conflicts (the changes list in `docs/acceptance-contract.md`, and the end of this file).
