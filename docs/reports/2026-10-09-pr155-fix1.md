# PR 155 fix round 1, 2026-10-09

The workflow calls tools/ci_retry_known_flakes.py. Both pytest passes write xunit1
JUnit reports. Failures and errors are merged per node across setup, call, and
teardown. Only 1 to 5 failing nodes, all explicitly allowlisted, may retry once.
The retry selects those exact IDs and succeeds only when its XML contains every
requested node with a passed outcome and no failure, error, skip, or xfail.
Each successful retry emits a warning with its defect ID, plus a summary.
Pytest exit codes 2 to 5 remain failures, with no retry of an unsuccessful first
pass. Missing or malformed XML fails closed. The cache is never consulted.
