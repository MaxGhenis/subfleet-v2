## What this does
Retention keeps a finished job's tree while another job still needs it, and admission fences those places. It closes four pin gaps that the #142 review found:
- `review_root` inside a tree;
- a job's `-o` output inside a tree;
- a case alias of a tree's name;
- a linked checkout whose git storage lives in a tree.

Submit records each job's `depends` (`review_root`, `out_path`, git storage) in canonical spelling. `worktree-in-use` compares the folded spellings of every live job's folders and dependencies. It replaces the SQL self-join, which grows quadratically, and #141's `COLLATE NOCASE`.

The design and the first build come from session 546e1b2c (2026-10-06), on `fix/retention-dependency-pins` (8f106c645). That session's worktree is gone, and it never opened a PR or handed the work off.
