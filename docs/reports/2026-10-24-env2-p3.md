## The change

**`subfleet/launch_env.py`**
- A second ContextVar, `_HELPER_WITHHELD`, holds a tuple of withheld-name
  callables, one per enclosing scope, outermost first.
- `helper_policy(policy, *, withheld=None)` appends its callable on entry and
  resets both ContextVars in `finally`.
- `_scope_withheld()` calls each callable and returns the union of their names;
  outside every scope it returns the empty set.
- `build_environment` computes `withheld = frozenset(withheld) |
  _scope_withheld()` before it reads any parent value. So a withheld name is
  still rejected before its value is read, and additions are applied after
  selection, so they still win.

**The scope entries**
- `daemon.py`, `_helper_environment` (it decorates `dispatch`, `_run_worker` and
  `_control`): passes `self._helper_withheld`. That new method returns
  `self._provider_environment.withheld()`, the exact set the daemon's launches
  withhold (`_withheld_references`: the stored lanes' references, and startup's
  ignored hooks). A Daemon built by hand without `_provider_environment` (unit
  tests do this) withholds nothing, as before.
- `timers.py`, `Timers._run_worker`: passes `Timers._withheld`, which returns
  the daemon's set (`references`, which is `Daemon._withheld_references`), or
  else the stored lanes' set. `_provider_environment` now uses the same method.
- `conversations/service.py`, `_resume_start`, and `conversations/wakes.py`,
  `_poll_prs`: each passes the daemon's `_helper_withheld`.
- `gate/service.py`, `dispatch`: passes the daemon's `_helper_withheld`.
  `preview` (the CLI's `gate --dry-run`) has no daemon. Nested inside
  `dispatch` in the daemon, it keeps the daemon's names (see "Choices").

**`subfleet/adapters/codex.py`**
- The isolated branch builds `env = build_environment(credential_env,
  withheld=<the adapter's provider_environment.withheld()>)`, or `()` for an
  adapter with no environment.
- `isolation.inspect_codex` then calls `build_environment(removals=…,
  environ=env, pass_names=tuple(credential_env))`. **It can't reintroduce a
  withheld name, from the code:**
  - it passes no additions, so every key it returns is a key of `env`, minus
    the removals;
  - every key of `env` that is withheld came from `credential_env`, its own
    additions (`build_environment` drops every other withheld key);
  - the only key it adds afterwards is `CODEX_HOME`, the lane's own home;
  - so a withheld name can reach the inspection only as one of the launch's
    own additions. A Codex launch's `credential_env` holds:
    - the policy's pass names, from which `additions()` has already dropped
      every withheld name;
    - `CODEX_HOME`, the lane's own home (`resolve_credential` gives env-kind
      credentials to Claude lanes only);
    - the CA source;
    - and the attempt's `TMPDIR` (`daemon.py:5568`, `:8039`).
    
    The CA source and `TMPDIR` are allowlisted names, so no lane can hold them
    (`refused_reference`);
  - inside a scope, its own selection withholds the scope's names again.

**Choices**
- **A nested scope keeps the outer names.** The policy's pass names are
  replaced by an inner scope, as before, but the withheld names accumulate:
  `pass` grants authority, and withholding only removes it. This matters
  because `gate.service.dispatch` runs inside `Daemon.dispatch`, and `preview`
  can run inside the gate's dispatch: had the inner scope replaced the outer
  names, it would have reset them.
- **The set is read at every call, never cached.** Each call costs one
  `store.list_lanes()` read for each distinct source around it: a scope whose
  source an outer scope already carries (the gate's inside `Daemon.dispatch`)
  adds none (review r1 of #262). The read is a read connection (C-3.7), or
  the reentrant store lock on a thread that already holds it (`WatchedLock` is
  an RLock), so no deadlock is possible. The launches already pay this cost.
- **A failing read propagates.** If reading the set raises, the helper fails
  rather than running with nothing withheld. That is the launches' behaviour
  too. `close()` shuts the pools down, waiting, before it closes the store
  (`daemon.py:10299`, `:10307`). So only a thread still running past its join
  timeout could read a closed store, and it would fail its helper, as a launch
  would fail.

## Invariants

Each is tested in `tests/unit/test_launch_env_round8.py`.

- **I1.** Inside a helper scope with withheld set W, for every parent
  environment E, every additions map A and every explicit `withheld` X,
  `build_environment(A, environ=E, withheld=X)` has no key in (W ∪ X) −
  keys(A).
  - Hypothesis, 150 examples, over nested scopes (W is their union), pass names,
    policy pass names and removals.
  - It also checks the stronger, exact form: the build equals the same build
    outside any scope with `withheld=W ∪ X`.
- **I2.** Outside any scope, `build_environment` is unchanged.
  - A differential against release's function, captured verbatim in
    `tests/fixtures/launch_env_release_217_env2.py`: Hypothesis, 150 examples,
    including invalid pass names, whose refusals must match too.
  - The same holds in a scope opened without withheld names (the CLI's `gate
    --dry-run`).
  - `test_i2_daemon_start_still_receives_every_lane_variable` shows that a
    scope-less build passes a lane variable by name (`daemon start`, C-12.3),
    and that the same build in a daemon scope withholds it.
- **I3.** The scope reads W at each call, not at entry.
  - `test_i3_the_scope_reads_its_names_at_each_call`: a set that changes
    between two calls in one scope gives two different selections, and the
    callable is not read when the scope opens.
  - `test_i3_a_lane_held_after_the_scope_opened_is_withheld`: claude-9 stored
    on the hook in the middle of one `Daemon._run_worker` call is withheld from
    that call's next build.
- **I4.** Nested scopes restore the outer W on exit, and an exception inside a
  scope doesn't leak W.
  - Hypothesis, 100 examples: random nests up to four deep, each level raising
    or not, checking the withheld names and the policy at every exit.
  - An example test, and a per-thread test (a scope on one thread withholds
    nothing on another).

**P3-1: the lint accepted an opt-out.**
- **Cause:** it checked only that a keyword named `withheld` was present.
- **The rule now** (`scopes_without_the_daemons_set`, with `opts_out` and
  `references`, in `tests/unit/test_launch_env_round8.py`):
  - every use of `helper_policy` is a direct call (`helper_policy(…)` or
    `module.helper_policy(…)`);
  - its `withheld=` is not a constant;
  - and it has no `**` keywords.

  Any other use of the name is refused where it is written, since the calls
  made through it can't be followed. That covers an `import … as` under
  another name, an assignment, an argument and an attribute read. An import
  under its own name is the one exception. The real package still lists only
  `preview`.
- **Why this rule:** it checks one AST node at a time and resolves no aliases,
  yet it refuses all three forms:
  - `withheld=None` is a constant;
  - `**` is a keyword with no name;
  - an alias needs a use of the name that is not a direct call.

  Refusing every constant, not only `None`, refuses nothing more in practice:
  no constant is a callable source.
- **`**` beside `withheld=`:** this can't opt out today, since a second
  `withheld` in the mapping raises `TypeError`. The lint refuses it anyway,
  because it can't read the mapping. `**` alone was already refused, as it
  has no `withheld=`; its test keeps that case.
- **Tests, red first:** each runs against a scratch module that also holds
  the real entries' spellings (`ACCEPTED`), so a lint that refused every scope
  could not pass:
  - `withheld=None`;
  - `**` alone and beside `withheld=`;
  - `helper_policy` through an `import … as`, an assignment, a module
    attribute and an argument (`functools.partial`).
