## Adversarial review

Two independent in-session Opus 5.5 reviewers ran against the whole range, for 36
and 25 minutes. One tried to make finalization raise on every retry or lose work.
The other attacked the transient classification, the optional probes, N2's admission
logic and the contract. Neither found an input that makes the salvage code itself
raise on every retry. Their reproductions are in `build/r3c2/review-final/` and
`build/r3c2/review-class/` (git-ignored scratch).

Fixed in `58cc2025` and `4454786e`. Each has a test that fails on `06353a16` for the
predicted reason (**17 failed** there, with 2 controls passing) and passes here:

1. **A git killed by a signal was an answer.** A negative return code read as "no
   HEAD" or "no branch", so a writable job on `main` passed the C-13.2 refusal. Now
   `_failure` (`salvage.py:136`) makes it transient everywhere, never "absent", and
   names the signal; a killed `add -A` raises at once; a killed `git worktree add`
   waits (`daemon.py:2708`). Tests: `tests/unit/test_salvage_optional_transient.py:59`
   (5 probes, including `validate_writable_workdir`), `:68`;
   `tests/fake/test_workspace_transient.py:286`.
2. **A tracked file replaced by a repository with no commit** (`rm x; git init x`).
   `ls-files -o` does not list `x/`, so salvage failed for good, held nothing
   (unrelated new work included), and the retry failed at admission. `diff-files`
   now names such candidates (`salvage.py:373`). The exclusion names only the
   directory, and the file's removal is still recorded (checked with real git).
   Tests: `tests/unit/test_salvage_unindexable.py:182` (seeded and empty index), `:202`
   (a committed repository still fails closed);
   `tests/fake/test_salvage_adversarial.py:124` (finalization, then the retry
   admitted).
3. **A reftable ref write on a full disk** (`reftable: transaction failure: I/O
   error`) read as permanent; it is now transient. Test: `test_salvage_unindexable.py:389`
   (new case).
4. **`GIT_DIR` and related variables in the daemon's environment** redirected every
   salvage call, which wrote its ref into that repository and reported success.
   `_git_env` drops them (`salvage.py:129`; the list is `subfleet/contracts.py:29`),
   and `subfleet daemon start` no longer passes them on (`subfleet/cli.py:2080`).
   Tests: `test_salvage_unindexable.py:496`; `tests/unit/test_daemon_verbs.py:241`.
5. **A long branch** whose sanitized ref part exceeded a file name made
   `update-ref` fail on every salvage from it. The branch part is now cut to 200
   (`salvage.py:538`). Test: `test_salvage_unindexable.py:595`.
6. **The held retry baseline left out a1's nested repository and said nothing.**
   The `salvage.baseline_held` event and any writable attempt's evidence
   (`baseline_skipped`, `daemon.py:3677`) now name what its start snapshot left out.
   Tests: `test_salvage_finalization.py:475`, `:495`.
7. **A submit whose top-level lookup failed after the job directory was written**
   left `jobs/<id>/` behind with no job. It is removed and the submit is exit 1
   (`daemon.py:1414`). Test: `tests/fake/test_workspace_transient.py:315`.

Also changed: the Changes pane no longer shows a checkmark beside "a nested
repository is not shown". C-6.8 now says the errno-less markers are transient
whatever their cause, and that a file name ending git's own line with those words
reads as them. That misreading is bounded: 3 tries at finalization, at most 8 waits
at admission.

Not fixed. These are follow-ups, each outside this incident's scope:

- **Receipt paths an agent could corrupt.** A directory or malformed JSON at
  `a<seq>/salvage.json`, `trees.json` or `exit.json` makes `_read_json` or the
  publish raise on every `_finalize`. This predates the branch and needs something to
  write into the attempt directory; the reviewer confirmed it.
- **A retried attempt's left-out repository is in no notice.** Only the evidence
  and the event name it; the job's final notice summarizes the final attempt only
  (C-15.1). This matches the contract's wording.
- **A dirty in-place baseline can be garbage-collected.** An in-place job's dirty
  `baseline_tree` is an unreferenced tree; `git gc --prune=now` makes that salvage
  fail (recorded at once, no ref). This predates the branch.
- **An ended turn's diff doesn't name its left-out repositories.** It would need
  `skipped` stored in the conversation store (a schema change). C-26.14 says the
  stored end's list is in the receipt and the evidence.
- **Two reasoned (not reproduced) resource issues.**
  - `subprocess.run` waits without a bound after killing a timed-out git that is
    stuck in uninterruptible I/O.
  - A killed `git add` leaves a partial `tmp_pack_*` behind, observed at 0.6 to 1.3
    MB each.
- **The submit-path `_git_prefix` and `_commit_holds_dir`** read a git that did not
  finish as "cannot say". That is advisory only, and they predate the branch.
