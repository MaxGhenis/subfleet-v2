Reviewed continuation guard (installed after parent authorization):

`sitecustomize-proposal.py` installs a CPython audit hook before tests import product modules. It refuses any ps/lsof/security/agent-secret/launchctl launch, all external gh commands, git arguments containing push, opaque shell/wrapper execution, unverified Python interpreters, Python `-S` bypasses and external executables outside a narrow allowlist. It logs only static refusal reasons and test code locations under the scratch directory, never argv, environment, locals or exception objects.

The source of `subfleet.procs` was inspected without importing it: module initialization binds ctypes symbols and initializes locks; it does not call ps, sysctl, libproc enumeration or process-reader functions. The proposal can therefore import that module at Python startup, replace all native `Darwin` readers with `InspectionError` refusals, prevent future native reader bindings, and force native spawn through the audited fallback. New synthetic kernel doubles remain usable. If guard initialization fails, it exits before test code, because ordinary sitecustomize import errors can otherwise be ignored by Python startup.

The guard must be installed in every interpreter's site-packages actually used by uv and test descendants. The parent observed uv's overlay interpreter under the scratch cache, so project `.venv` alone is insufficient. A temporary repository-root copy covers Python children that overwrite `PYTHONPATH` with the repository. Preserve any existing file and remove these job-only files before finishing.

Expected consequences: process-backed fake fixtures should skip at `process_inspection_available`; unmarked native-premise tests may fail or skip due the guard, so explicitly exclude known native-premise nodes and report those exclusions. Remaining tests with injected process/kernel boundaries continue to exercise the changed code. Denied environment-sensitive probes are not product failures. A Python audit hook is not an OS sandbox: opaque native or shell descendants could bypass it, which is why the proposal denies shell/wrapper commands and unverified executables rather than attempting to parse arbitrary shell text.
