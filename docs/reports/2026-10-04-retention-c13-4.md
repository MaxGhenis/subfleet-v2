# Retention preservation validation

Retention now protects an eligible job when a non-exempt regular file lacks archive coverage, including a path its accepted salvage skipped. It returns the job in `protected` and records `unarchived path: worktree/<path>` in `deferred`. The same check precedes committing a retirement resumed from an archived journal. This work starts at #76's merged head `c30211edc3751ea6956de833c07f9bc298e75e60`; the comparison baseline is release/217 `f832e6b8`.

## Cause and fix

The original failing test assumes release/217's snapshot-only retention. At `f832e6b8`, `subfleet/retention.py:203` runs plain `git add -A` in a temporary index. Git refuses the nested repository with no commit, so retention protects the job even when `salvage_referenced_elsewhere` releases its ref pin. `SalvageResult.skipped` records that omission (`subfleet/salvage.py:535`).

#76 walks and copies the nested repository independently of salvage. Inspection of the original failing fixture found 31 nested entries, including 19 regular files with stored copies and the exact `inside.txt` bytes. The archive exception therefore applies to that fixture: its original failure does not demonstrate lost bytes. A new normal-path regression checks the archive and restores the entire nested repository byte for byte. The original named regression now withholds archive coverage for `inside.txt` and verifies protection with a reason, preserved rows and registration, and released leases.

There was nevertheless a coverage gap: `subfleet/retention_archive.py:1775–1776` at `c30211ed` skips verification when an entry has no `store`. An uncovered file can pass verification, and `_drop_unreferenced` can delete its orphaned copy. The new `_require_file_bytes` guard (`subfleet/retention_archive.py:98`) rejects a regular file without stored bytes, a verified blob omission, or a regeneration proof. Existing hash readback rejects corrupt copies. The guard runs in `_Builder._verify_store` and `Retirement._final_check`: `subfleet/retention.py:551` resumes archived journals without rebuilding, so checking only the builder was insufficient. C-8.4, C-13.4, and revision 7 of the archive design now describe both checks and the archive exception.

The Hypothesis property generates skipped or non-skipped salvage, present or absent private bytes, and missing, corrupt, or verified archive copies (20 generated examples plus five explicit examples). An independent Git lookup proves the bytes are absent from salvage. Unsafe outcomes must preserve the exact original tree; safe outcomes must pass archive verification, import the bundle into an independent clone, and restore every entry except the rewritten root gitfile.

## Validation

On final production code `9a333411e0e791d75f3ebe633cc95c370a43f96d`, Python 3.12.14 passed 468 test invocations covering all 467 required nodes, with zero failures, errors, or skips. The sweep property ran twice to preserve 40 generated examples under the time limit. All 41 successful foreground slices finished within 412.04 seconds; their summed duration was 3,546.96 seconds. Fresh collection and JUnit node counts match exactly, allowing only that intentional repeat. Python 3.14.7 also passed the four focused tests: missing coverage, complete restoration, archived-journal recovery, and the new Hypothesis property (273.30 seconds).

All test processes run in the foreground, with a nine-minute timeout per slice. The scope includes every `tests/unit/test_salvage*.py` and `tests/unit/test_retention*.py` node, plus whole files containing other maintenance callers on `c30211ed`: `test_policy_support.py`, `test_timers_busy_read.py`, `test_timers_retention.py`, and `tests/fake/test_resume_contract.py`. The saved Git grep and AST scan include direct calls and aliases. Collection, exact slice membership, JUnit results, durations, and the runner are in [the evidence directory](2026-10-04-retention-c13-4/).

Before the restart guard, Python 3.12.14 passed all 466 then-collected nodes in 40 slices (maximum 429.61 seconds); Python 3.14.7 passed 142 salvage and worktree nodes in 15 slices. These historical results are distinguished from the final validation above.
