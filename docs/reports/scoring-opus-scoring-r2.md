# Complementarity and A+B score

Adopting B as the plan of record, these parts of A are additive rather than competing, and each fills a hole B's revision 4 did not reach:

1. **"Approvals, external actions, and reset policy"** — the typed external action (`pending`/`executing`/`confirmed`/`failed`/`unknown`) with intent and a stable operation key persisted *before* the remote call, plus "an expected-base preflight is not an atomic base lock" and "if the response is ambiguous, inspect the actual PR and merged revision before retrying". B generalises this only for reset credits; its Gates section says `subfleet-gate` "keeps its semantics", so B has no action state machine at all. Highest-value single import.
2. **"Lifecycle, recovery, and cancellation"** — (a) "A new coordinator process acquires an OS-level singleton host lock before changing state… SQLite write serialization alone does not prevent two schedulers from launching work." B relies on launchd `KeepAlive` while also shipping `subfleet daemon start`, and never states a singleton rule. (b) Cancellation and result acceptance serialized with both orders specified. (c) Parent cancellation propagating to descendants with aggregated budgets — B caps `max_child_jobs` at 8 but says nothing about propagation.

# Disputed claims

1. **Plan A: "My default implementation would be Go, SQLite, one local coordinator" at "8–12 engineer-weeks" — unverifiable and, on the evidence offered, optimistic.** The justification is stated as preference ("Go is my preference for a fresh implementation, not an explanation for today's issues"), and every provider interaction in the real system is a CLI invocation, a JSON stream, a keychain read, or a `git` subprocess — work a second language does not reduce. The estimate must absorb 15,084 lines of Python and 3,464 of bash, re-expression of roughly 18,000 lines of pytest (Plan A states it "did not run the existing test suite"), and a milestone 5 of 8–12 days that contains packaging, imports, shadow comparison, per-account transfer, rollback, retention, backup/upgrade tests *and* a canary soak. The plan does label these as planning estimates, which is why I call it unverifiable rather than wrong — but it is a Go rewrite proposed to a one-maintainer Python/uv shop with the effort priced as if the rewrite were in Python.
2. **Plan A: "The basic executor should not inject repository-writing instructions because it detected a broad keyword" — contradicted.** The trigger is the resolved permission mode, not a keyword: `delegate.py:1069-1071` reads `if not args.no_preamble:` / `if sandbox == "workspace-write":` / `preamble.append(PREAMBLE_WRITE)`, and the sandbox comes from the task (`README.md:549-550`: "build defaults to `workspace-write`; every other semantic task defaults to `read-only`"). An opt-out already exists in `--no-preamble`. The design conclusion — that workflow templates belong in the job manifest — survives; the diagnosis behind it does not.
3. **Plan B: "README line 108 describes a 10-point handicap; the picker sorts the login strictly last" — the second half is right, the first half is contradicted.** `README.md:107-109` says "Claude keeps its worst-window headroom score, active-app protection, and lower-in-flight tiebreak", and the string `handicap` does not appear in `README.md` at all; the 10.0 default is a code fact (`cli.py:1476-1477`, `claude.py:309`). Since this line sits in the section whose purpose is to pin *where the specification and the behaviour disagree*, attributing a number to the README that the README does not contain weakens exactly the artifact the rebuild is meant to test against. A second, smaller instance of the same imprecision: Appendix B reports "five blockers and twelve majors" from `reports/G-review.md`, which contains 5 blocker rows and 15 major rows — a count B's own disposition table gets right.
