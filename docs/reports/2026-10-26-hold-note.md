# Operator holds name their latest release bound (D-RAMP-HOLD-LABEL)

The lane ramp holds lanes until six hours from now as a safety bound, then
releases them in rotation within minutes. Text that described an operator hold
as an account closure with a provider reset made sessions read that bound as a
six-hour wait.

This build starts at #263, `581550f80fdb`. That change already supplies
`lanes hold --note`, stores it in `source_event` as `operator: <note>`, validates
it through `contracts.hold_note`, and withholds malformed stored sources. It
already supplies the `held` verdict, the app's neutral "Held" label, separate
fleet-empty cause counts, and no per-lane alert for holds. Those decisions,
the schema, the validator and admission are retained. Its existing prose was
`held by operator until <T>: <note>`; this build makes the latest-release
bound explicit.

## What this adds

1. `render._held_text` owns the wording:
   `<home>: held by the operator[: <note>] (until <T> at the latest)`.
   Every human display of a hold uses it. The shared `render.lane_home` is also
   `alerts._home`; it uses the home, credential reference, then lane id. Recorded
   decisions that carry only a lane id use that id. Fleet-empty bodies retain
   their causes, counts, keys and severities, with each held closure rendered
   through this function. Provider-limit, credits, cooldown and auth-dead text
   stays byte for byte the same.
2. #267's conversation `held` wait kind is ported. Its details include the
   hold's stored note and latest release bound.
3. #267's pin-refusal split is ported. A hold and a provider limit sharing the
   same scope and end get separate text; the provider sentence keeps its words.
   The first green attempt exposed an omitted part of the port:
   `pin_unadmittable` returned only scope, end and reason, discarding the source
   and lane name. A real noted hold therefore rendered as a withheld note on
   the lane id. The smallest completion carries the hold source through #263's
   strict `hold_source_shown` reader and carries the home/reference as
   explanatory metadata. It changes no lane judgment. A real-store test also
   pins that an externally written credential-shaped source stays withheld.
4. Hold acknowledgements print the active stored row the daemon returns.
   A past or present `--until` is refused in the daemon, with exit 2 and reason
   `hold-until-past`, before a closure or event is written. An earlier/equal end
   retains #263's refresh rule; the response carries the applied note and `kept`,
   and the CLI says the stored until and note were kept and this call's were
   not applied. For an older #263 reply without `kept`, the CLI derives it
   from the returned closure and replaces that reply's requested-note echo with
   the stored note, including in JSON. `lane.held` records the applied end and
   note inside the same transaction. If a reply has no active stored hold, the CLI exits non-zero
   and says it is not in force. An older daemon's reply without the note field
   warns that it recorded the hold without its note, exiting 69, in text and
   JSON alike.
5. No per-lane hold alert is added. #263's alert rules and verdict precedence
   remain in force.
6. No new validator is added. r1's three credential-shaped inputs, whitespace
   and empty notes, and its nonprintable inputs are pinned as refused at both
   the CLI and daemon before any writes.
7. C-9.6 describes the wording, full display list, acknowledgements and applied
   audit values; C-18.4 uses the same hold wording. The version-3 change log
   records D-RAMP-HOLD-LABEL.
