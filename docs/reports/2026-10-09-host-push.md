# Host-side branch push — fix rounds 1 to 3 of #158

Push policy remains disabled by default. The branch includes `release/217`
`caa1665b0` through merge `20b0d92df`, preserving both the tier preferences and
probe recovery changes alongside host push. Release is schema 6; this PR stays
at schema 7. Commits are on `feat/host-push` in this workspace's `.git-local`;
shared Git metadata and the caller's checkout are read only.

The job writes a full, self-contained bundle advertising exactly `HEAD` at
`.subfleet/push.bundle` inside the directory where it starts. The absolute path
is supplied in `SUBFLEET_PUSH_BUNDLE` and the prompt preamble. Use
`mkdir -p .subfleet && git bundle create .subfleet/push.bundle HEAD`, adding
`--git-dir=.git-local` when the job commits there. The delivery folder is excluded
from its allocated checkout and the delivery path is cleared before an attempt.

The daemon opens the worktree root as a directory handle, opens every component
below it with `O_NOFOLLOW` (`O_DIRECTORY` for directories), and opens the final
file nonblocking. Only a regular file within the size cap is accepted. It copies
bytes from that descriptor into the accepted attempt directory and verifies only
that copy. Replacing the source name after open cannot substitute another bundle.
Missing files, FIFOs, links, directories and oversized files become `push_error`.

Every host Git subprocess for submit, allocation, verification and publication
uses a fresh bare quarantine and a fixed host environment. Hooks, fsmonitor,
replacement refs, system/global config and config includes are disabled. Only
directly configured host credential helpers are passed to remote operations.
The daemon reads checkout metadata and copies baseline objects as data (each
metadata file only as a capped regular file, round 2 below); it never
runs publication Git against a job-controlled `.git`, `.git-local` or worktree.
Allocated push checkouts are standalone. Retention archives their `.git`
directories as bytes and never executes their config or hooks.

Protected and reserved names compare NFC-normalized and casefolded. Branches
remain ASCII and must pass the existing syntax restrictions. A case twin of an
existing remote branch is refused; an existing branch requires the exact spelling
owned by this family and a previous successful publication. Every introduced
commit must descend from the recorded base and satisfy the commit cap. `.github`
is compared by root entries, without recursive diffs. The recursive symlink and
gitlink scan streams at most 1,000,000 entries per tree. All verification Git
calls share one 300-second deadline, with a 60-second cap per call; output,
symlink counts and target sizes are separately bounded. Git process groups are
killed on timeout, and stderr is discarded to avoid exposing credentials.

`job_owned_branches` reserves `(remote_key(remote), fold(branch))` for the root
of the non-independent job family; the recorded URL and exact branch spelling
are retained for publication and audit. Equivalent HTTPS/SSH GitHub spellings
share one reservation. A fetched existing remote tip must be an ancestor of the
verified tip. Publication uses only plain
`git push <recorded URL> <verified SHA>:refs/heads/<declared branch>`.

One dedicated push thread queues publication without tying up pool workers.
Acceptance commits first, and every Git call runs outside store transactions.
A durable `job_pushes` pending row precedes intake. `pushing_at` and the ownership
reservation are committed immediately before `git push`. A restart before that
marker safely restarts verification, at most three intakes; after it, the notice
says interrupted and requires inspection of the remote. Completed re-exports
never push twice. Push failures preserve accepted state and exit status. A push
lease keeps the job until export settles. Audit and ownership survive retention.
The CLI checks the existing capability protocol for `push.v1` before submitting
any opted-in single or batch job; older daemons receive no such submission.
No MCP tool exposes `push_branch`. Besides `run --push-branch`, a `run --batch`
manifest job may carry it, and the CLI is the only client that sends it.

## Residual risks and limits

The existence check before plain push remains. If an external writer creates the
branch at an ancestor of the job's tip between the check and push, Git
fast-forwards it and the family records ownership of a branch it did not create.
The daemon's queue and reservation serialize Subfleet families; receive-side
rules would be needed to eliminate this external race. There is no `--force`,
`--force-with-lease`, `+` refspec or deletion.

Existing push or PR workflows and preview deploys can run the job's changed code
with this repository's secrets. Refusing `.github/` changes does not prevent
that execution. The contract states this residual risk explicitly.

Rolling back below schema 7 requires restoring the pre-migration store backup:
a schema-6 daemon refuses a schema-7 store. Schema migrations are additive and
preserve existing jobs without granting them push authorization.

Allocation copies baseline objects and runs strict object verification under the
existing per-call cap; large-repository allocation remains unbenchmarked. Full
history bundles must fit the configured cap (256 MiB by default); alternates,
partial-clone fetching and incremental bundles remain unsupported.
