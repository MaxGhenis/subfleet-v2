# Host-side branch push — d1098 option A

Push remains disabled in code and `default_policy.json`. This change does not
enable or edit live policy, supply lane credentials, or publish a network branch.

The intake convention is `jobs/<job>/a<sequence>/push.bundle`, a full bundle
advertising exactly `HEAD`, created with `git bundle create <path> HEAD`. The
daemon copies a bounded regular file into a private directory before inspecting
it. It verifies, fetches and checks objects, ancestry, each introduced commit's
paths, and each introduced tree's links in a fresh bare quarantine. Git has an
empty template, disabled hooks and fsmonitor, no system/global config or includes,
no replacement refs, and a fixed host environment. Only directly configured host
global credential helpers are passed to remote operations. Git's process group
is killed on timeout; credential helper stderr is never published.

Submit reads origin and HEAD as text, including linked worktrees and packed refs,
and records them in the job row. It discovers the remote default from a quarantine
and refuses unknown defaults. To avoid the existing worktree/salvage path executing
lane config, opted-in jobs get a standalone checkout allocated from copied object
files through a quarantine. The host subsequently consumes only the attempt's
bundle; it does not salvage an opted-in job through its Git metadata. Local object
alternates, partial-clone fetching, config includes, and incremental bundles are
deliberately unsupported for this intake. A job must supply a complete bundle.

`job_owned_branches` reserves `(remote, branch)` for the root of a non-independent
job family before publication and records successful tips. Existing branches need
that successful ownership record and an ancestor check of their fetched tip. An
independent child starts its own family. `job_pushes` has a unique job key and a
durable pending record before I/O; completed operations replay without another
push. An interrupted pending operation becomes a failure requiring manual
reconciliation. These audit and ownership rows survive job retention. Acceptance
and exit status remain independent of every push failure. Acceptance also takes
a `push:<job>` lease: the existing indexed export query recovers a crash before
publication, and retention keeps the bundle until export releases that lease.

Two constraints need the hub's attention. The specified plain, non-forcing
`git push URL SHA:refs/heads/branch` has no atomic create-only condition. Host
serialization and a durable family reservation prevent competing daemon claims;
an external writer could still create a compatible remote branch after the host's
check and before Git advertises refs. Non-fast-forward updates remain rejected.
Eliminating that external race requires receive-side enforcement or a changed
publication protocol; this implementation does not add a prohibited lease or
force option. Also, this repository contains no submission MCP server: the MCP
equivalent is the additive `push_branch` field on its existing submit wire contract,
available to clients without introducing a second submission service.

worktree config, includes, hooks and Git environment variables.
