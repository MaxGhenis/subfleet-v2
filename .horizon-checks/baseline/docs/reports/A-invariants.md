"A run where every probe is a network error is treated as offline: no alerts" (`README.md:381`). `subfleet/watchdog.py:271` computes the Claude scoped-limit conditions before the offline check, and `subfleet/watchdog.py:277-281` returns `[offline(silent), *conditions]`. Those scoped conditions are `severity: critical` (`subfleet/watchdog.py:254-264`) and are not marked silent, so a fully offline cycle can still page.
2. "one recovery notice when auth/fleet conditions clear" (`README.md:380`). The recovery prefix list at `subfleet/watchdog.py:732-736` covers revoked, refresh-revoked, no-auth, duplicates, suspect, fleet-empty, free-plan, lane-auth, lanes-empty, and mirror-stalled. It omits `codex-fleet-low`, so the "only 1 dispatchable lane left" fleet condition never sends an all-clear; `codex-capacity-expiring`, `claude-limit`, `codex-app-shadow`, and `codex-resets-idle` likewise never recover.
3. "Claude keeps its worst-window headroom score, active-app protection, and lower-in-flight tiebreak" (`README.md:108`) describes the old 10-point handicap. The handicap still exists (`subfleet/capacity.py:27,1202`), but the real rule is stronger: the desktop login now sorts strictly last in the delegate picker (`subfleet/delegate.py:568-584`) and is excluded from `_best_dispatchable` whenever any other lane is dispatchable (`subfleet/capacity.py:1315-1322`). The README understates the standing order it cites elsewhere.
4. "`/tickle` in any Claude session runs it (skill at ~/.claude/skills/tickle)" (`README.md:202-203`). Nothing in this repository installs, references, or verifies that skill; `subfleet hooks install` writes only the three `bin/subfleet-hook` entries (`subfleet/hooks.py:47-54`). The claim is unverifiable from the repo and unenforced by it.
5. "the old command and `CARPOOL_*` variables stay aliased for a transition week" (`README.md:3-4`). The aliasing loop is unconditional and has no expiry in any of the five entry points (`bin/subfleet-claude:81-86`, `bin/subfleet-codex:76-81`, `bin/subfleet-guard-hook:59-64`, `bin/codex:17-22`, `bin/subfleet-hook:23-28`). The transition week ended on 2026-08-30 by the README's own dating.
6. "an already-detached run keeps its selected model, rotates eligible lanes" (`README.md:552-553`). Rotation inside the runner depends on `-A`, which the delegate appends only when the lane was auto-picked (`subfleet/delegate.py:1231-1232`); a detached run dispatched with `-a` (or a gate peer, which pins `-m`) does not rotate. The README states rotation unconditionally.
7. "how that session was told (`notify`: pushed / parked / surfaced)" (`README.md:292-294`). `_notify_state` also returns `pending` and `none` (`subfleet/run_ledger.py:682-695`), which the table prints; the documented vocabulary is incomplete.
